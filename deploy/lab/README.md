# Authorized lab (G0.4c)

A local DNS lab for the first tool chain (Subfinder → DNSx) that runs entirely in containers
on this host: an authoritative resolver for a lab zone and a local passive-source stub, on
an internal network with no route off the machine. It makes the G1 demo reproducible without
internet and without any external target.

```sh
make lab-up      # start the lab, generate the throwaway CA, wait until it is healthy
make lab-check   # inventory consistency + Subfinder and DNSx runs compared to fixtures
make lab-status  # health and boundary (internal network, no published ports)
make lab-down    # remove only compose project aegis-lab and the throwaway CA
```

`images.env` drift from it.

## Topology

| Service | Container | Address | Role |
| --- | --- | --- | --- |
| `dns` | `aegis-lab-dns` | `10.114.53.53` | CoreDNS, authoritative for `lab.aegis.test.` only; every other name is REFUSED |
| `passive` | `aegis-lab-passive` | `10.114.53.80` | local `crt.sh` stub, serves one committed fixture to one authorized query |

The network `aegis-lab-lab` is `internal: true`, has no published ports on the host, and a
run container gets no default route (see [Sandbox rules](#sandbox-rules-for-the-runs)).

### Zone `lab.aegis.test.`

| Name | Type | Value |
| --- | --- | --- |
| `lab.aegis.test.` | NS | `ns1.lab.aegis.test.` |
| `ns1` | A | `203.0.113.53` |
| `www` | A / AAAA | `203.0.113.10` / `2001:db8::10` |
| `api` | A | `203.0.113.30` |
| `mail` | A / MX | `203.0.113.20` / `10 mx1.lab.aegis.test.` |
| `mx1` | A | `203.0.113.25` |
| `vpn` | CNAME | `www.lab.aegis.test.` |
| `txt` | TXT | `aegis lab zone; not a real domain` |

`ghost.lab.aegis.test` is deliberately absent (NXDOMAIN probe) and `example.com` is
deliberately outside the zone (REFUSED probe): the lab checks its own boundary instead of
assuming it.

### Passive-source stub

Subfinder's crt.sh source sends `GET https://crt.sh/?q=%25.<domain>&output=json`. For a
non-public zone a real source has nothing to return; the lab stub answers that one query for
`lab.aegis.test` from `fixtures/crtsh.lab.aegis.test.json`, which contains the inventory
names plus decoys (a duplicate, a wildcard and an out-of-zone name) so the adapter's filtering
is exercised. The Subfinder run gets an `/etc/hosts` entry `crt.sh → 10.114.53.80` and
`SSL_CERT_FILE` pointing at a throwaway CA generated by `make lab-up`; it never reaches a
third party and cannot reach one (internal network). The stub returns 403 for any other
query and logs every request.

## Runs and fixtures

| Run | Command | Expected (fixture) |
| --- | --- | --- |
| Subfinder | `make lab-subfinder` | `fixtures/subfinder.expected.json`: the three names the stub offers, after Subfinder drops the duplicate, the wildcard and the out-of-zone name |
| DNSx | `make lab-dnsx` | `fixtures/dnsx.expected.json`: A/AAAA/CNAME for every NOERROR probe, NXDOMAIN for `ghost`, REFUSED for `example.com` |
| Both | `make lab-check` | inventory consistency, then both runs |

`scripts/lab/compare_results.py` compares the raw JSONL of the pinned image with the
committed fixture; a changed A record, a missing host or an unexpected status fails the
command (deliberately broken fixtures are the negative control). Raw output, the exact
command and its SHA-256 stay under `deploy/lab/.run/runs/<kind>-<UTC>/` (git-ignored), so a
run can be audited without committing generated data.

The lab is not part of the contract CI job (`.github/workflows/contracts.yml`): it pulls the
scanner images and needs SELinux relabelling on the self-hosted runner, while the contract
gate must stay fast and hermetic. `make lab-check` is run on demand and its evidence is in
this file and in the G0.4c report.

## Sandbox rules for the runs

Run containers use the G0.2 flags that apply to a one-shot verification container:

- rootless Podman, current uid:gid (`--userns=keep-id --user $(id -u):$(id -g)`);
- only `aegis-lab-lab` (`--internal`, no host network); no published ports;
- `--cap-drop ALL`, `--security-opt no-new-privileges`, read-only rootfs with tmpfs;
- cgroup limits from the pinned manifest: DNSx `0.5` CPU / `256m` / 300 s, Subfinder `1`
  CPU / `512m` / 120 s (the manifest cap is 900 s; the stub answers in well under a second);
- the resolver is pinned by address (`-r 10.114.53.53`), not discovered from the host; the
  Subfinder run passes `-t 1` and `-rl 5`, a fixed conservative value for the local stub
  (campaign snapshot caps are enforced by M05/the adapter, G1.1c/1.3b);
- shared read-only inputs use SELinux `z` (one label for every container) and unique output
  directories use `Z`; a per-container `Z` on a shared directory would lock the other
  container out (see the runbook note below).

Not covered here, by design: the collector's byte/file caps, raw hashing and parser
isolation (G1.3a), the L7 broker (`networkAccess: broker`), and mapping `record_types` to
DNSx flags (adapter, G1.3b). This lab proves the target set and the two runs, not the
product runner.

## Runbook notes

- **Root cause of a real failure here:** binding `deploy/lab/fixtures` with `:Z` from the
  DNSx run relabelled it to that container's SELinux MCS category and the Subfinder stub
  then got `PermissionError` on the next request. Two containers sharing a read-only path
  must use `:z`; the fix and the two-pass `make lab-check` that would have caught it are in
  `scripts/lab/lib.sh` and `deploy/lab/compose.yaml`.
- The CoreDNS image is a single static binary: an in-container healthcheck is impossible.
  `make lab-up` proves readiness from the lab network with the pinned DNSx image instead.
- `make lab-down` deletes `deploy/lab/.run/tls` (throwaway CA and keys). Run evidence under
  `deploy/lab/.run/runs/` is kept; delete it manually when it is no longer needed.
- Changing the zone: edit the zone file, `inventory.json` and the expected fixtures
  together; `scripts/lab/check_inventory.py` fails on any drift before a run starts.

## Dịch vụ cho chuỗi discovery (G1.6)

Lab có thêm các dịch vụ bản cũ (pin digest, `cap_drop: ALL`, không mở port ra host) để quét port, nhận diện version và khớp CVE: `web-legacy` (nginx 1.18.0), `app` (Tomcat 9.0.30, 8080/8009), `ssh` (OpenSSH 9.9, case âm), `cache` (Redis 6.0.5), `legacy-httpd` (Apache httpd 2.4.49); địa chỉ và CVE kỳ vọng ở `inventory.json`. Lệnh: `make lab-naabu`, `make lab-fingerprintx`, `make lab-httpx`, `make lab-httpx-proxy` (fingerprintx build bằng `make lab-build-fingerprintx`); `make lab-check` chạy cả các lệnh này. Job chỉ vào mạng lab khi RoE của campaign khai `network_profile: lab`; file profile một mình không quyết định. Redis và AJP 8009 hiện không lộ product/version (fingerprintx chưa có bản release đọc INFO; không có detector AJP) — xem backlog.
